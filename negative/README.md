# 负例集

这个目录里的数据**故意写错**，唯一用途是检验 `validate.py` 本身。

校验器说「0 错误」只有在它能抓出错误时才有意义。一个永远返回通过的校验器和没有校验器，结果完全一样。所以这里的做法是：先手工注入已知的违规，再看校验器是否一个不落地报出来。

## 用法

```bash
python3 selftest.py
```

输出：

```
负例集：negative
  注入的规范违反点   44 个
  校验器实际报错     44 条
  命中 44 · 漏检 0 · 误报 0

自检通过：每条注入的违规都被精确命中，且没有多余报错。
```

**漏检** = 某条规范在代码里失效了，校验器抓不到。
**误报** = 出现了预期之外的报错，说明负例数据里有非预期问题，或某条规则过严。

两种情况都会让脚本以退出码 1 结束。

## 文件

| 文件 | 作用 |
| --- | --- |
| `terms.yaml` / `relations.yaml` / `cases.yaml` / `hotspots.yaml` | 注入违规的负例数据，用 `# N01` 形式标注每处注入 |
| `expected.yaml` | 期望命中清单，逐条写明该违规应由哪条报错命中 |
| `../selftest.py` | 比对脚本 |

## 编写纪律

1. **除注入点外，其余字段一律填成合规值。** 否则会产生无法归因的噪音，把真正的漏检淹掉。
2. **一处注入对应尽量少的报错。** 例如「缺必填字段」要挑不会被枚举检查二次报错的字段，否则一处注入产生两条报错，清单就要写两条。
3. **注意 YAML 行内映射的标点陷阱。** `where: "TERM-9005.polysemy[1]"` 必须加引号——方括号和英文逗号在 `{...}` 行内映射里是保留字符，不加引号会被解析成别的东西。这个坑本文件自己踩过一次。
