# 社会学术语知识系统

社会学概念知识库，由**三个概念群**组成、以网状结构相连：

| 概念群 | 核心问题 | 术语 |
| --- | --- | --- |
| 社会不平等 | 社会不平等是如何被生产、维持与再生产的？ | 28 |
| 社会秩序与越轨 | 社会秩序如何可能？越轨又是如何被定义与控制的？ | 8 |
| 社会行动与理性化 | 现代社会的行动是如何被理性化地组织起来的？ | 8 |

这不是一份术语词典，而是一条完整的数据生产链路：**标注规范 → 结构化数据 → 自动校验 → 负例自检 → 标注者一致性检验 → 可检索的界面（列表 + 网络两种视图）**。当前 44 条术语、64 条概念关系（含 10 条跨群桥接）、18 条经典案例、4 条社会热点，每条结论都能指回具体文献。

## 为什么值得做

社会学训练给我的是一堆散在书里的概念：阶级和阶层到底是不是一回事？「社会资本」在布迪厄、科尔曼、帕特南笔下指的是三种不同的东西。这些分歧在论文里靠脚注处理，一旦要变成**数据**就必须显式建模——谁的定义、哪一版、和谁冲突、依据在哪一页。

这个项目就是把这些隐性判断逼成显式字段的过程。它同时是一次自我检验：能不能把人文社科的模糊材料，做成可校验、可追溯、可被他人复用的数据资产。

## 快速开始

```bash
python3 validate.py                  # 校验数据；0 错误才算通过
python3 selftest.py                  # 负例自检：57 个注入点是否全部命中
python3 agreement.py --codebook demo/codebook.yaml annotations/*.yaml
python3 build_site.py                # 生成 site/index.html（自包含，双击即可打开）
```

无第三方依赖，只需 Python 3 与 `pyyaml`。

## 界面

静态检索页支持**按流派、按应用场景、按关键词**三种查法，可叠加使用，条目按首现年份排序。

![按流派筛选](screenshots/界面-按流派筛选.jpg)

界面有两套视图：**列表**按首现年份排序，**网络**把术语按关系连成图——群内连线用该群的颜色，跨概念群的关系画成橙色虚线。概念群、流派、应用场景三种筛选对两种视图同时生效。

![网络视图](screenshots/界面-网络视图.jpg)

只勾一个概念群，图上就只剩这个群自己的节点与群内连线，可以看清一个群内部的结构。

![概念群筛选](screenshots/界面-概念群筛选.jpg)

点「冲突论」得到阶级、社会封闭、社会排斥、文凭通胀四条；搜索「布迪厄」得到他提出的七个概念。点网络图上的节点会跳回列表并高亮对应词条。每条术语可展开多义性、概念关系、经典案例、社会热点四个折叠区。

**关系分三层显示**，因为它们本来就是三种东西：`证据` 是文献里的原句（可核对），`编者解读` 说清这条边接在哪一点上，`边界` 挡住最容易过度推论的方向。没有这一层，读者只能看到一个「机制」标签，剩下全靠自己猜。

![关系解读](screenshots/界面-关系解读.jpg)

**热点条目按「相符之处 / 不符之处 / 解析」三段写**。只写相符，归属会越挂越宽；只写不符，条目会失去用途。解析负责把一件事拆成几层，逐层说明哪层对上了哪个概念、哪层只是被公共讨论混在了一起。

![热点相符与解析](screenshots/界面-热点相符与解析.jpg)

分析范畴（如「阶层」）带独立徽章，且不渲染案例栏——它是划分现象的维度，本就不该有案例，显示一个「经典案例（0）」会让人误以为缺数据。

![分析范畴](screenshots/界面-分析范畴-阶层.jpg)

## 四条设计原则

1. **概念层稳定，实例层流动。** 术语与关系长期有效；案例与热点持续流入，热点过期只降级、不影响概念层。
2. **每条结论必须可追溯。** 定义、关系、归属都要能指回具体文献或链接，没有出处的不入库。
3. **归属必须有反面。** 把一个现象归入某个概念时，必须同时写出它**不符合**该概念的哪些部分。`mismatch` 字段为空会被校验器直接拦下——这是防牵强附会的核心机制。
4. **枚举值封闭。** 流派、应用场景等字段只能取预设值。允许自由填写会让标签体系在几十条之后彻底失效。
5. **群内可以密，群间必须克制。** 每个术语归属一个概念群，跨群桥接每对群上限 5 条、且禁止标注「等同」。早期版本干脆禁止跨群关系，后来发现那样会丢掉「不平等」与「越轨」之间真实存在的联系，于是改为受限放行——代价是要多写一条校验规则。

## 数据规模

| 层级 | 数量 | 说明 |
| --- | --- | --- |
| 概念群 | 3 个 | 每群一个核心问题；术语只能归属一个群 |
| 术语 | 44 条 | 覆盖全部 11 个流派、12 个应用场景 |
| 概念关系 | 64 条 | 8 种关系类型（当前用到 7 种，`等同` 群内可用、群间禁用）；每术语上限 12 条，防过度连接 |
| 跨群桥接 | 10 条 | 不平等↔越轨 5 条、不平等↔理性化 5 条；每对群上限 5 条 |
| 经典案例 | 18 条 | 每处归属都写了不符之处 |
| 社会热点 | 4 条 | 限定 3–5 个：热点是入口不是主体 |
| 多义性条目 | 15 条 | 同一术语在不同作者笔下的定义分歧 |
| 关系解释 | 64 条 | 每条关系都写了「这条边在说什么」（`explain`） |
| 关系边界 | 57 条 | 「这条边不意味着什么」（`boundary`），对立/借用/转化类优先写 |
| 热点解析 | 4 条 | 每条热点按「分层 → 逐层定符合度 → 点出混淆处」写成一段 |

## 这套结构与数据运营工作的对应

| 本系统 | 对应 VLM / 多模态数据工作 |
| --- | --- |
| 术语多义性条目 | 同一图像在不同标注规范下的多重归属 |
| 归属块（一个热点挂多个术语） | 多标签标注 |
| `mismatch` 必填 | 边缘样本必须记录不符合项 |
| `match` 与 `mismatch` 成对必填 | 标注必须同时记录「对上什么」与「没对上什么」，防止只挑合用的部分 |
| `evidence`（引文层）与 `explain`（解读层）分栏 | 数据里区分「原始证据」与「标注者解读」，解读不得当作证据使用 |
| `confidence` 三档 | 标注确信度分级，容忍不确定性 |
| 双人独立复标 + 算一致率 | 标注者间信度检验 |
| 封闭枚举 + 字段白名单 | 标签体系封闭，防止自由填写导致体系失效 |
| 规范即配置、可回溯重判 | 标注规范迭代与历史数据回溯 |
| `negative/` + `selftest.py` | 用已知坏样本验收质检脚本 |
| 概念群 + 跨群桥接上限 | 数据分域与跨域样本配额，防止单一来源或单一场景压垮数据集 |
| 热点复审、过期降级 | 数据生命周期管理 |

## 开发中真实踩过的坑

**1. 一个逗号悄悄吃掉了一半的出处。**
`relations.yaml` 用行内映射写法，`source: Lin 2001, Social Capital` 里的英文逗号被 YAML 当成字段分隔符——`source` 只剩 `Lin 2001`，后半段变成一个假字段。6 条关系的出处被静默截断，而校验**全部通过**。修复后加了 `schema.fields` 字段白名单，多余字段一律判错。讽刺的是，后来写负例期望清单时我又踩了同一个坑（`where: TERM-9005.polysemy[1]` 里的方括号）。

**2. 单阈值查重会产生误报。**
在同一套方法做图像质检时发现：单一 dhash 阈值会把「打伞的人 / 斑马 / 飞鸟」三张无关图判成重复。改成两段式——pHash 先做候选择，再用灰度余弦验证。

**3. 一致性系数不能只报一个数。**
Krippendorff's α 在多标签数据上随编码本口径显著变动：只计入被提及的术语，α 假性偏低（实测出现过 0.667 的完全一致率对应 α = −0.088）；计入完整编码本又会因大量「双方都未标注」的空单元而偏高。因此本项目**只报区间**（当前 0.847～0.878），并与完全一致率、平均 Jaccard 对照解读。

## 已知限制

- 全部页码标注为 `【页码待核】`，需人工核对原文后方可转 `已复核`。
- 4 条热点的 `source_url` 仍是占位符；`HOT-0001` 已过复审期，待降级或延期。
- 多义性条目的 `school` 字段在作者流派归属存在争议时留空，与早期条目写法不一致。
- 18 条经典案例的归属块由 `rationale` 改名而来，**内容仍是早期写法**，比热点的「相符之处」薄——案例的相符之处尚未按新要求重写。
- `explain` 与 `boundary` 是编者解读，不是引文；页码核验只覆盖 `evidence` 层，解读层没有「原文页码」可核，只能靠复核人重读判断。
- 术语分布偏重（文化社会学 11 条、社会分层与流动 18 条），健康与医疗、网络与数字社会、城市与空间各仅 1 条。
- 三个概念群只有两对之间有桥接（不平等↔越轨、不平等↔理性化）。「社会秩序与越轨」与「社会行动与理性化」之间目前 0 条——科层制的规则执行与越轨的界定其实有联系，但还没找到可引用的原句，宁可留空也不硬连。

## 规范变更

`标注规范细则.md` 记录每次判定规则的变更与影响范围，当前 v8（数据规范 `schema.yaml` 为 v6，两者版本号不同步：细则记的是判定规则，schema 记的是字段与约束）。数值化的规则全部落在 `schema.yaml`，改规范只需改这一个文件，历史条目按新版规范回溯重判。
